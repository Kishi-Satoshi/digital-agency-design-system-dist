# PowerPoint（.pptx）の審査と直し

PowerPoint の資料を、テクバン独自の Office 基準（`references/office-standard.md`。スライド編・初版）で審査し、指摘を直す。Claude Code・Cowork では審査役（`reviewer`）と直す役（`fixer`）がこの手順で動く。ブラウザが要らないので、**チャットでも窓口が自分でこの手順を行ってよい**。

資料を**作る**のはこのスキルの担当ではない（slide-techvan に任せる）。審査結果の報告書を作るときは、Web と同じく DADS のデザインの HTML にする（`roles/review.md` の「報告書にするとき」）。

パスはこのスキルのフォルダ（以下 `SKILL_DIR`）からの相対パス。先に SKILL.md の「基準の優先順位」「守るもの」「重大度と印」と、`references/office-standard.md` を読んでおく。

## 守ること

- **スライドマスター・レイアウト・テーマは変えない**（テンプレートは基準より優先する）。直す道具も、これらが変わるときは保存しない。
- テンプレート（マスター・レイアウト）に書かれた文字（フッター・コピーライトなど）の指摘は、作成者の問題として数えない。審査の道具も外して別に表示する。直すならテンプレートの持ち主に確認する。
- 資料のフォルダから上に `DADS-PROTECT.md` があれば読む。「ブランド色」に書かれた色は、テーマの色と同じに扱う（道具も指摘から外す）。
- 元のファイルは変えない。直したものは `<名前>.dads-fixed.pptx` に保存する。上書きするかは利用者が決める。

## 審査

1. **記録の置き場所**：資料と同じフォルダの `.dads-review/<YYYYMMDD-HHMMSS>-<ファイル名>/`（例：`.dads-review/20261024-101500-提案書.pptx/`）。日時は `date +%Y%m%d-%H%M%S` で実際の時刻を取る（作った値にしない）。
2. **道具を動かす**：
   ```sh
   bash scripts/audit/audit.sh --env     # disposable なら次の行に --install を付ける
   bash scripts/office/pptx_audit.sh <資料.pptx> --out <記録の置き場所> --deps <依存の置き場所>
   ```
   - 依存の置き場所は SKILL.md の「道具の場所」のもの（プラグインでは `${CLAUDE_PLUGIN_DATA}/audit`）。チャットでは `--deps` を付けず、`--install` を付ける。
   - 終了コード 3（Python の部品が無い）：各自の PC では、入れてよいかを利用者に聞いてもらうため「未点検。入れてよければ --install で点検できる（約 70MB）」と返して止まる。
   - LibreOffice が無いときは、構造の点検だけが行われ、`summary.md` に「描画の点検は未点検」と出る。そのまま審査を続け、文字サイズ・コントラスト・見た目は「確認できなかったこと」に書く。
3. **道具の記録を読む**：`summary.md` の候補と、`result.json`（`findings` の `slide`・`shape`。描画の行ごとの文字サイズ・色・コントラストは `pages`）。
4. **スライドの画像を見る**（`slide-NN.png` を開く）：道具では分からない基準を確かめる。
   - S5 色だけで伝えていないか（凡例・強調・良し悪し）
   - S11 文字量と行間、S12 はみ出しと重なり
   - S3 代替テキストの中身が画像の役割に合っているか（`result.json` の `slides[].images[].alt` と画像を見比べる）
   - S2 本文の読み上げ順が見た目の順か（道具はタイトルが最初かだけを見る）
5. **候補を確かめて指摘にする**：重大度は SKILL.md の決まりどおり（WCAG の A＝致命的、AA＝重要、基準だけに当たるもの＝軽微で「基準」の印）。テンプレート由来のものは「守るもの」と書く。
   - 12〜18pt の文字は、本文なら S9 の指摘、注記・出典・表やグラフの中の文字なら指摘にしない。画像を見て判断する。
   - 背景が画像の上の文字のコントラストは推定値なので、画像で確かめる。
6. **記録を書く**：`roles/review.md` の findings.md の書式で書き、`bash scripts/audit/audit.sh --findings <記録の置き場所>` に標準入力で渡す。「場所」はスライド番号と図形名・id（例：`スライド 3「Picture 6」（id 7）`）。直す役が使うので、図形の id は必ず書く（無い指摘は、図形の中の文字の一部を書く）。
7. **返す**：`roles/review.md` の「返し方」と同じ。

## 直す

1. 審査の記録（`findings.md`・`result.json`）を読む。無ければ先に審査する。
2. 直す順番と確認（Web と同じ考え方）：
   - WCAG の致命的・重要は確認せずに直す。
   - 「基準」の印だけのもの（12pt 未満の文字、テーマ外の色・フォントなど）と軽微は、一覧で見せて了承を得たものだけ直す。
   - テンプレート由来のもの、`DADS-PROTECT.md` に書かれたもの、レイアウトを変えないと直せないもの（タイトルのプレースホルダが無いスライドなど）は、どの場合も確認する。直す道具ではできないので、利用者に PowerPoint で直してもらうか、方法を相談する。
   - 代替テキストは、スライドの画像を見て、その画像が伝えていること（グラフなら結論と主な数字）を書く。何を伝える画像か分からないときは、推測で書かずに利用者に聞く。飾りは「装飾用」にする。
   - リンクの文字を変えるときは、行き先が分かる言葉にする。行き先が分からなければ聞く。
3. 直す内容を JSON にして、直す道具を動かす（op の一覧は `scripts/office/pptx_fix.py` の先頭に書いてある）：
   ```sh
   python3 scripts/office/pptx_fix.py <資料.pptx> <直す内容.json> --pydir <依存の置き場所>/py
   ```
   - 図形は `shape`（審査の記録の id）か `find`（図形の中の文字の一部）で指定する。
   - 文字の色を変えるときは、テーマの色（`tx1` など）を優先し、直接の色は最後の手段にする。
   - 終了コード 1 は「直せない指示があった（何も保存していない）」。理由を読み、その指示を外すか直してからやり直す。
4. **再審査**：直した `<名前>.dads-fixed.pptx` を、審査役に深い審査をさせる（記録は `.dads-review/<日時>-<ファイル名>-after/`）。審査役を呼べない環境では、道具で記録だけ取り、「再点検が必要」と返す（窓口が審査役を呼ぶ）。
5. **返す**：直した指摘の番号と内容、直さなかった指摘と理由（確認待ち、テンプレート由来、レイアウトの変更が要る など）、再審査の結果、保存した `.dads-fixed.pptx` の場所、修正前後のスライド画像の場所。
